## Реализовано

- Задачи 5–6 выполнялись первыми по запросу пользователя: container ResizeObserver, однострочная панель с More, сохранение scroll/wrap, реальное измерение кнопок и составных цветов, инертная измерительная строка, координатор меню и рабочая палитра внутри overflow.
- Задача 1: постоянный server-issued scope на канонический корень; auth-protected endpoint; IndexedDB с ревизиями, условным удалением, отдельными writerId и транзакционным переносом путей.
- Задачи 2–3: локальное сохранение с debounce/max-wait, CAS обычного редактора, состояния сохранения, список восстановления/сравнения/экспорта/удаления, сохранность черновиков после logout и смены vault, перенос путей после rename. Метаданные изменений распространяются через BroadcastChannel; содержимое документов по нему не передаётся.
- Задача 4: editable unified diff CodeMirror с выбором фрагментов, базовый/локальный/серверный текст, отдельная копия, повторный 409 с сохранением результата. Canvas проверяется как JSON с nodes/edges, используется whole-document режим. Большие тексты получают редактор без интерактивного diff.
- Исправлены дополнительные регрессии интеграции: session создаётся при hydrate восстановленного workspace; базовая версия обновляется после каждой подтверждённой записи; старый API-response не очищает новые правки; смена vault сначала сохраняет текущий документ.

## Решения реализации

- Ruling: используем текущий checkout, поскольку предыдущие исправления и план находятся здесь; не переносим и не откатываем чужие изменения.
- Ruling: ResizeObserver пересчитывает раскладку непосредственно, без отложенного requestAnimationFrame. В скрытом Electron окне rAF оставлял старую раскладку после сужения. Пересчёт чистый; React state меняется только при изменении partition.
- Ruling: визуальный diff — unified CodeMirror: локальный текст является результатом, серверный — original, база доступна отдельным просмотром. Это даёт адаптивный редактор и действия по фрагментам без трёх широких колонок.
- Ruling: восстановление открывается через видимый список Local drafts и окно сравнения; серверная запись всегда требует явного действия пользователя.
- Ruling: после сохранения отдельной копии показываем её путь, сохраняя открытый нерешённый оригинал. Это не запускает запрещённое автосохранение оригинала при переключении.
- Ruling: существующий helper безопасного JSON в settings.ts приватный и специализированный. Registry использует тот же write-temp/rename подход, отдельную очередь и уникальное временное имя.
