# Обмен фрагментами заметок с Microsoft Word и Excel

План доработки webobsidian · 9 ноября 2026 г.

В режиме чтения пользователь выделяет фрагмент заметки и выбирает **«Копировать для Office»**. В обратную сторону он копирует фрагмент в Word или диапазон в Excel, ставит курсор в редактор заметки и нажимает **Ctrl+V**. Единица переноса — выделенный фрагмент, в том числе текст, таблица и несколько картинок в одном выделении.

## Что должно получиться

| Сценарий | Критерий приёмки |
|---|---|
| Заметка → Word | Заголовок, список, внешняя ссылка, редактируемая таблица и две картинки сохраняют порядок. Сохранённый DOCX показывает картинки после закрытия webobsidian и отключения от хранилища. |
| Заметка → Excel | Выделенная таблица занимает ожидаемый прямоугольник листа. Пустая ячейка внутри строки сохраняет своё место, кириллица читается. |
| Word → заметка | Абзацы, заголовки, списки, выделение жирным и курсивом, ссылки и простые таблицы превращаются в редактируемый Markdown. Полученные из буфера картинки сохраняются как вложения в местах исходных изображений. |
| Excel → заметка | Для диапазона сохраняются все строки, столбцы и отображаемые значения, включая результат формулы, даты и ведущие нули, если они представлены в буфере. Диапазон без заголовков сохраняет первую строку данных. |

## Порядок реализации

### 1. Проверить, какие данные реально передают Word, Excel и браузер

- [ ] В тестовом хранилище подготовить заметку, документ Word и диапазон Excel по таблице выше. Включить значение `00123`, формулу с результатом `150`, пустую ячейку, вертикальную черту и перенос строки внутри ячейки.
- [ ] В настольных Word и Excel на Windows выполнить копирование и проверить в браузере доступные HTML, текст и файлы изображений. Для Word проверить отдельно одну картинку и две картинки внутри текста. Для Excel проверить, приходит ли вместе с таблицей её растровый снимок.
- [ ] На этом же этапе проверить экспорт картинки вместе с текстом в Word и повторное открытие DOCX без доступа к хранилищу. По результату выбрать подтверждённый способ передачи изображения внутри фрагмента. Зафиксировать версии Office и браузера, доступные форматы и обезличенные входные образцы в `web/tests/fixtures/officeClipboard/`. Если комбинация форматов теряет часть содержимого, указать это в результате испытания.

### 2. Добавить «Копировать для Office» в режим чтения

- [ ] В `web/src/components/Preview.tsx` сохранить копию выделенного DOM-диапазона до открытия контекстного меню. Поддержать выделение с картинкой даже при пустом текстовом представлении. Использовать только содержимое текущей заметки.
- [ ] В новом `web/src/lib/officeClipboard/export.ts` собрать HTML выделения и текстовое представление. Сохранить структуру таблицы и минимальное оформление границ, убрать кнопки просмотра и служебные элементы. Для выделенной таблицы собрать текст по строкам и табуляциям. Данные вложенных изображений получить через существующий доступ к вложениям.
- [ ] Записывать оба представления в буфер одной командой. При отказе браузера или недоступном вложении сообщать, что именно удалось скопировать, и предлагать доступный вариант. Добавить название команды и сообщения через действующий механизм локализации.
- [ ] Проверить в `web/tests/officeClipboardExportBrowser.test.ts` копирование одной картинки, таблицы и фрагмента абзаца, отказ в доступе к буферу и доступность обычной команды «Копировать».

### 3. Преобразовать содержимое Word и диапазоны Excel в Markdown

- [ ] В новом `web/src/lib/officeClipboard/import.ts` разобрать HTML из буфера в упорядоченные фрагменты текста и изображения. Переносить видимое содержимое и разрешённые ссылки, пропускать служебную разметку Office и активное содержимое. Использовать доступный HTML таблицы в первую очередь, даже если рядом передан её снимок.
- [ ] Для таблиц экранировать вертикальные черты и сохранять переносы внутри ячейки. Если в исходнике нет заголовков, добавить пустую строку заголовков Markdown и перенести все строки данных. Для объединённых ячеек развернуть диапазон в прямоугольник, поместить значение в левую верхнюю позицию, остальные позиции оставить пустыми.
- [ ] При отсутствии HTML распознавать прямоугольный диапазон по табуляциям и границам строк с учётом кавычек. Обычный текст, код, неоднозначный одиночный фрагмент и вставку в блок кода передавать существующему обработчику.
- [ ] В `web/tests/officeClipboardImportBrowser.test.ts` сравнить исходные образцы с ожидаемым Markdown. Проверить также таблицу без заголовков, один ряд, одну ячейку, пустой крайний столбец, многострочное значение и пропуск сценариев из HTML.

### 4. Подключить Ctrl+V и сохранение картинок

- [ ] В `web/src/components/Editor.tsx` подключить обработчик вставки CodeMirror для редактируемых Markdown-заметок. Считывать форматы в момент события. Обработанное событие должно иметь одного владельца, чтобы штатная вставка CodeMirror и обработчик изображений в `web/src/components/Workspace.tsx` не вставили содержимое повторно.
- [ ] Переиспользовать загрузку через `api.upload` и построение ссылки через `formatInternalLink`, учитывая исходную заметку и настройку папки вложений. Сопоставлять картинки с их местами по доступным данным буфера. Для недоступной картинки сохранять подпись или метку на её месте и сообщать об этом. Проверить отдельно отсутствие дубликата при двух представлениях одной картинки.
- [ ] Подготовить весь фрагмент и заменить выделение одной операцией редактора, чтобы Ctrl+Z отменял вставку целиком. Если во время загрузки сменились заметка, содержимое или выделение, сохранить пользовательские правки, сообщить о прерывании и показать пути уже загруженных файлов. При частичном сбое сохранить доступный текст и положение пропущенного изображения.
- [ ] В `web/tests/officeClipboardPasteBrowser.test.ts` проверить оба режима редактора, замену выделения, отмену, чистый текст, отдельный скриншот, режим чтения, сбой второй загрузки и переключение на другую заметку во время загрузки.

### 5. Принять результат в приложениях

- [ ] Запустить профильные тесты из корня проекта командой `node --import tsx --test web/tests/officeClipboard*.test.ts`, затем `npm run typecheck`, `npm test` и `npm run build`. Убедиться, что браузерные сценарии действительно выполнились.
- [ ] В Edge и Chrome на Windows выполнить четыре сценария из таблицы в настольных Word и Excel. Отдельно прогнать круговой обмен «заметка → Word → новая заметка» с двумя картинками и «Excel → заметка → Excel» с пустыми ячейками. Сверить порядок, размеры диапазона и значения, проверить редактирование ячейки в Word.
- [ ] Зафиксировать результаты по приложениям и версиям. При реализации обновить `PRD.md` и `IMPLEMENTATION_PLAN.md` в части фактически поддержанных сценариев.

Первый выпуск рассчитан на перенос содержимого и структуры. Формулы Excel переносятся отображаемыми значениями. Точное воспроизведение стилей Word и восстановление формул Excel выходят за рамки этой доработки.

## Выполнение 9 ноября 2026

Реализованы экспорт HTML/текста через команду контекстного меню, автоматический
импорт HTML/TSV в редактор, вложения, защита от вставки в изменившуюся заметку и
отмена всей вставки одним действием. В режиме чтения восстановлена структура
частично выделенной таблицы. В Excel переносятся отображаемые значения. Картинки
из data URI сопоставляются с файлами по содержимому, оставшиеся — по имени либо
по порядку при одинаковом количестве. Неоднозначные картинки получают видимую
метку, чтобы исключить подстановку чужого изображения.

Проверено: 8 новых тестов конвертации/вставки, всего 24 профильных теста PASS,
полный typecheck PASS, production-сборка в отдельный каталог PASS.
Независимое ревью выполнено, замечания по границам таблиц, выделению ячеек,
сопоставлению изображений, литеральным значениям TSV и заголовкам исправлены.

Остаются непроверенными графический браузер и реальный обмен с настольными
Word/Excel, включая сохранение картинок в автономном DOCX. Electron/Chrome
завершаются при старте из-за Windows AppContainer. Стандартный npm test прерывается
на ошибках EPERM. Повтор сервера последовательно дал 244 PASS, 147 FAIL и
10 SKIP, с ошибками сетевого/файлового доступа среды, включая EACCES для loopback.

Развёртывание ожидает доступного SSH. Попытка соединения с root@10.10.1.21:22
завершилась Permission denied на уровне подключения. Подготовлен каталог
build/office-clipboard-release с public.tar.gz, manifest.json и Deploy.ps1.
Сценарий определяет актуальный базовый образ, использует существующую процедуру
CT102 с резервной копией, проверкой health/asset hashes и откатом при сбое.
Синтаксис PowerShell и Python проверен. Установка этим сценарием пока не выполнялась.

### Подготовка к публикации в форке

Финальное независимое ревью обнаружило три ошибки экспорта из настоящего
readonly-редактора: служебные `cm-widgetBuffer` ошибочно обрабатывались как
картинки, классы CodeMirror теряли смысл заголовков/выделения/списков после
очистки HTML, а текстовый вариант склеивал соседние абзацы.

Добавлена нормализация DOM редактора в семантический HTML, удаление служебных
элементов до обработки картинок, сохранение обрамляющих элементов частичного
выделения и явных границ блоков в обычном тексте. Регрессионные проверки
воспроизвели ошибки до исправления. После исправления прошли все 10 профильных
тестов, включая настоящий компонент Editor в режиме чтения с изображением,
списками, частичным выделением жирного текста и ячеек таблицы; web typecheck PASS.

После исправлений полный typecheck и `npm run build` прошли. Полный `npm test`:
398 server PASS, 3 SKIP; 531 web PASS, 0 FAIL. Ревью не проверяло фактический
результат в настольных Word/Excel; оформление Office и восстановление формул
остаются вне обещанного объёма.
